# 08 · 权限、安全、人工确认与部署

[English](../en/docs/08-security-confirmation-and-deployment.md) · [目录](../README.md)

Agent 安全的核心不是“让模型更听话”，而是限制一次错误判断最多能影响什么。OWASP 将过度功能、过度权限和过度自主性列为 Excessive Agency 的根因；NIST 的生成式 AI 风险管理资料则强调在生命周期中治理、测量和管理风险。[OWASP Excessive Agency](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/) · [NIST Generative AI Profile](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)

教学代码把批准策略单独放在 [`approvals.py`](../tutorial/src/mini_agent/approvals.py)：被标记为 `requires_approval=True` 的工具默认由 `DenyAll` 拒绝；只有应用提供另一种明确策略时才可能继续。模型不能通过在回复中说“用户同意了”来替自己批准。

## 1. 三个最小化

| 原则 | 落地方式 |
|---|---|
| 最小功能 | 只向该任务暴露必需工具，将“读”与“写/删”拆分 |
| 最小权限 | 工具使用当前用户身份和最小 scope，不共享高权限万能凭证 |
| 最小自主性 | 高风险动作先生成可核对预览，用户确认后再执行 |

权限必须在工具或下游系统重新检查，不使用“system prompt 说可以”作为授权证据。

## 2. 把所有外部内容当作数据

用户输入、网页、邮件、文档、图片文本、检索片段和工具结果都可能包含提示注入。用边界标识它们，不将其中的指令提升为系统规则；对工具参数和输出再做 Schema、权限和业务校验。提示注入的影响与 Agent 能力和业务场景相关。[OWASP Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)

## 3. 人工确认要确认具体动作

有效确认页应显示：动作、目标资源、关键参数、预期影响、是否可撤销、凭证身份和确认有效期。“继续吗？”不足以让用户判断风险。

确认必须绑定到动作摘要或不可变请求 ID。如果模型在确认后修改了目标、金额或其他关键参数，原确认失效，必须重新展示。

## 4. 秘密、日志和供应链

- 密钥从密钥管理或进程环境注入，不写进代码、提示、工具 Schema 或日志。
- 日志实施字段级脱敏、访问控制和保留期；调试模式不应默认导出完整上下文。
- 锁定 SDK、MCP Server 和工具依赖来源与版本，更新前审查权限、启动命令和能力变化。

OWASP 的 LLM/GenAI Top 10 将供应链、敏感信息披露、不当输出处理和无界消耗等列为独立风险类别。[OWASP LLM Top 10](https://genai.owasp.org/llm-top-10/)

## 5. 部署边界

将 API 服务、Agent worker 和高风险工具放在可单独限流和授权的边界。worker 使用任务级身份，限制网络出口、CPU/内存、执行时间和并发数。工具副作用使用业务幂等键，任务队列明确区分可重试与不可重试错误。

准备紧急停止开关：可以按工具、用户、租户或版本禁用写操作，而不必等待重新部署整个应用。

## 上线检查表

- [ ] 工具功能、凭证权限和 Agent 自主性均最小化；
- [ ] 外部内容按不可信数据处理；
- [ ] 高风险动作的确认绑定具体参数并会过期；
- [ ] 密钥、日志和执行记录有脱敏与访问控制；
- [ ] 依赖和 MCP Server 锁定来源与版本；
- [ ] 超时、限流、资源额度、幂等和紧急停止均已测试；
- [ ] 上线后持续复盘失败轨迹和高风险拦截。
