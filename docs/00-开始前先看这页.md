# 00 · 用 DeepSeek 跑通第一个 Agent

[English](../en/docs/00-read-this-first.md) · [目录](../README.md)

这一页假设你只会一点 Python，甚至还没调用过模型。第一课不安装本地模型，也不使用假模型演示：你将直接调用 DeepSeek 在线 API，让真实模型决定调用工具，再由本地 Python 程序执行工具并回传结果。

## 1. 今天要完成什么

普通模型调用通常是“一次请求、一次回复”。第一个 Agent 会完成下面的多步闭环：

```text
用户：杭州天气如何？
  ① 把问题和 get_weather 工具说明发给 DeepSeek
  ② DeepSeek 返回 get_weather({"city":"杭州"}) 工具请求
  ③ 程序校验工具名、调用 ID 和参数
  ④ 程序执行本地 get_weather 函数
  ⑤ 程序把结果作为 tool 消息交回 DeepSeek
  ⑥ DeepSeek 根据工具结果生成最终回答
```

DeepSeek 官方工具调用流程同样要求应用接收工具请求、执行函数并回传结果；官方也提醒模型生成的参数不保证永远是合法 JSON，因此执行前必须校验。[Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/) · [Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)

模型不会直接执行你电脑上的 Python 函数。它提出结构化请求，真正的执行权始终在你的程序里。

## 2. 准备 DeepSeek API Key

在 [DeepSeek API Keys](https://platform.deepseek.com/api_keys) 创建 Key，并确认账户能够调用付费 API。不要把 Key 粘贴进 Python 文件、提交到 Git，或发在公开聊天中。

macOS / Linux：

```bash
export DEEPSEEK_API_KEY="你的 DeepSeek API Key"
```

Windows PowerShell：

```powershell
$env:DEEPSEEK_API_KEY="你的 DeepSeek API Key"
```

环境变量只对当前终端会话生效。教程源码只读取 `DEEPSEEK_API_KEY`，不会把它写进项目文件。

## 3. 安装教学项目

先确认 Python 版本：

```bash
python3 --version
```

需要 Python 3.10 或更高版本。然后执行：

```bash
git clone https://github.com/normalpeople553/HowToBuildAgent.git
cd HowToBuildAgent
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e tutorial
```

Windows PowerShell 把创建和激活环境的两条命令换成：

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
```

`venv` 只是为 Python 依赖创建隔离环境，不会下载或运行本地大模型。模型运行在 DeepSeek 服务端。

## 4. 发起第一次真实 Agent 调用

确保 Key 已经在同一个终端中设置，然后运行：

```bash
mini-agent-demo
```

这条命令会发起真实 API 请求并可能计费。当前默认型号是 `deepseek-v4-pro`；DeepSeek 官方当前 Chat API 列出的可用 ID 包含 `deepseek-v4-pro`，并支持工具调用。[Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/) 价格会变化，请直接查看 [Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing/)。

成功后会显示最终回答和执行轨迹。具体措辞可能变化，但应该包含：

```text
model_request
model_response（请求工具）
tool_started: get_weather
tool_finished: get_weather
model_request
model_response（最终回答）
turn_finished
```

`get_weather` 返回的是教学模拟值，所以最终回答必须明确说明不是真实天气。真实的是 DeepSeek 的模型请求与工具选择，不是真实天气数据。

## 5. 如果没有成功，先看哪里

| 现象 | 首先检查 |
|---|---|
| 提示未设置 Key | Key 是否在运行命令的同一个终端中设置 |
| 401 / authentication | Key 是否完整、有效，环境变量是否多了引号或空格 |
| 402 / 余额相关错误 | DeepSeek 账户余额和计费状态 |
| 429 | 限流、并发或账户配额；保留响应头和错误体再判断 |
| 找不到 `mini-agent-demo` | 虚拟环境是否激活，是否成功执行 `pip install -e tutorial` |
| 工具参数错误 | 保留脱敏后的错误文本；不要直接执行模型生成的未知参数 |

不要把所有 429 都自动解释成“请求太快”；余额、账户级限制和服务策略都需要结合官方返回的错误体判断。

## 6. 按这个顺序读代码

1. [`demo.py`](../tutorial/src/mini_agent/demo.py)：读取 Key，创建真实 DeepSeek Agent，发起任务。
2. [`real_deepseek.py`](../tutorial/src/mini_agent/real_deepseek.py)：把消息和工具发送给 DeepSeek，再把回包转换为内部结构。
3. [`agent.py`](../tutorial/src/mini_agent/agent.py)：完成模型请求、工具执行、结果回传和停止判断。
4. [`example_tools.py`](../tutorial/src/mini_agent/example_tools.py)：实现工具函数与参数校验。
5. [`tools.py`](../tutorial/src/mini_agent/tools.py)：将模型可见 Schema 映射到允许执行的本地函数。

读完后先回答：DeepSeek 负责决定什么？Python 程序负责决定什么？为什么必须有 `tool_call_id`？

## 7. 再运行测试，不要拿 API 当测试框架

真实调用成功后，再运行本地回归测试：

```bash
python3 -m unittest discover -s tests -p 'test_*.py'
```

测试使用固定的脚本响应来覆盖未知工具、非法参数、重复调用 ID、轮数上限和批准拒绝。它不会请求模型 API，也不是教程默认模型；它只是让相同错误每次都能稳定重现。

真实调用证明当前 Key、型号、网络和厂商链路在这一次能够工作；固定测试证明本地控制逻辑在指定输入下符合预期。两者都需要，不能互相替代。
