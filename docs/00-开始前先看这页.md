# 00 · 开始前先看这页

[English](../en/docs/00-read-this-first.md) · [目录](../README.md)

这一页假设你只会一点 Python，甚至还没调用过模型。目标不是先背概念，而是在 15 分钟内跑出一个完整 Agent，再带着运行结果读代码。

## 1. 先知道今天要完成什么

普通模型调用通常是“一次请求、一次回复”。本课程的第一个 Agent 多做了一件关键的事：模型可以请求一个由程序预先注册的工具，程序校验并执行工具，然后把结果交回模型，直到模型给出最终回答。

官方函数调用流程也是这个多步骤结构：发送可用工具、接收工具请求、由应用执行、回传工具结果，再接收最终回答或下一批工具请求。[OpenAI Function calling](https://developers.openai.com/api/docs/guides/function-calling) · [DeepSeek Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)

今天的演示会完成这条轨迹：

```text
用户：杭州天气如何？
  ① 模型请求 get_weather({"city":"杭州"})
  ② 程序确认工具已注册、参数合法
  ③ 程序执行模拟天气函数
  ④ 程序把结果作为 tool 消息加入历史
  ⑤ 模型读取结果，返回最终正文
```

模型不会真的操作 Python 函数。它只生成一个结构化请求；真正的执行权始终在你的程序里。

## 2. 准备环境

先确认 Python 版本：

```bash
python3 --version
```

需要 Python 3.10 或更高版本。然后在你准备存放项目的目录执行：

```bash
git clone https://github.com/normalpeople553/HowToBuildAgent.git
cd HowToBuildAgent
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e tutorial
```

这些命令分别在做：

| 命令 | 作用 |
|---|---|
| `git clone ...` | 下载这份说明书和教学代码 |
| `cd HowToBuildAgent` | 进入项目目录 |
| `python3 -m venv .venv` | 创建只属于当前项目的 Python 环境 |
| `source .venv/bin/activate` | 在当前终端启用这个环境 |
| `pip install -e tutorial` | 安装教学包；`-e` 让你改完源码后不用重复安装 |

Windows PowerShell 使用下面三条环境命令：

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e tutorial
```

不要把 API Key 写在命令历史、源码或 Git 提交中。第一课完全不需要 Key。

## 3. 跑第一个 Agent

```bash
mini-agent-demo
```

你应当看到最终回答，以及类似下面的七步轨迹：

```text
model_request
model_response（请求 1 个工具）
tool_started
tool_finished
model_request
model_response（不再请求工具）
turn_finished
```

文字和字数可能随代码版本变化，但顺序不应变化。这里的“模型”是 `ScriptedModel`：它按脚本返回预先写好的两步响应，因此不联网、不计费、每次结果一致。它不是在冒充真实模型，而是专门用来学习控制流和编写稳定测试。

如果命令找不到，先确认终端提示符前面是否出现 `(.venv)`，再重新执行 `python -m pip install -e tutorial`。也可以直接运行：

```bash
python -m mini_agent.demo
```

## 4. 用测试确认不是“碰巧能跑”

退出虚拟环境也能运行当前仓库的离线测试：

```bash
python3 -m unittest discover -s tests -p 'test_*.py'
```

测试除了成功路径，还会检查：

- 未注册工具会在执行前被拒绝；
- 同一批工具请求不能复用调用 ID；
- 最后一个允许的模型轮次不能再偷偷开始工具执行；
- assistant 的调用 ID 与 tool 结果能够对应；
- 文档中的本地链接与中英文配对存在。

这些测试不证明任何厂商当前可用；它们证明的是我们自己的 Agent 循环在固定输入下按预期工作。真实模型测试和本地逻辑测试解决的是两个不同问题。

## 5. 先按这个顺序读代码

不要一上来逐行读所有文件。按下面的顺序：

1. [`demo.py`](../tutorial/src/mini_agent/demo.py)：看它怎样准备两次模型回复并启动 Agent。
2. [`agent.py`](../tutorial/src/mini_agent/agent.py)：只读 `Agent.run()`，把每个分支和刚才的七步轨迹对应起来。
3. [`example_tools.py`](../tutorial/src/mini_agent/example_tools.py)：看工具函数和参数校验怎样分开。
4. [`tools.py`](../tutorial/src/mini_agent/tools.py)：看模型可见的说明怎样映射到真正处理函数。
5. [`models.py`](../tutorial/src/mini_agent/models.py)：看 `ModelClient` 为什么能同时容纳脚本模型和真实模型。

读完后，请先尝试回答三个问题：

- 删除 `messages.append(... role="tool" ...)` 会发生什么？
- 为什么未知工具不能自动按名字寻找同名 Python 函数？
- 为什么最后一轮收到工具请求时，程序选择停止而不是继续执行？

下一章会带你用执行顺序回答它们：[01 · 从模型调用到第一个 Agent](01-从模型调用到第一个Agent.md)。

## 6. 什么时候连接真实模型

至少先做到：能画出五步闭环、能找到工具白名单、能解释调用 ID、能让全部离线测试通过。之后再运行：

```bash
export DEEPSEEK_API_KEY="你的 Key"
mini-agent-deepseek
```

这会发起真实请求并可能计费。当前适配器使用 `deepseek-v4-pro`、DeepSeek 官方 API 地址和 Chat Completions 工具调用流程；型号身份、价格入口和厂商字段继续由[模型说明书 DeepSeek 目录](https://github.com/normalpeople553/HowToCallLLM/tree/main/models/deepseek)维护。不要仅凭一次成功就推断其他型号或厂商完全兼容。

## 7. 第一课的完成标准

- [ ] `mini-agent-demo` 可以运行；
- [ ] 能指出第一次和第二次模型请求之间发生了什么；
- [ ] 知道天气结果是本地模拟值，不是真实天气；
- [ ] 能运行离线测试；
- [ ] 没有配置或提交任何 API Key；
- [ ] 能用自己的话解释“模型提议，程序决定并执行”。

满足这些条件，就可以进入第一章。遇到问题时，请保留报错原文、运行命令和 Python 版本，但先删除 Key、用户名、绝对路径和业务数据再分享。
