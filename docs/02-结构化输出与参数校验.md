# 02 · 结构化输出与参数校验

[English](../en/docs/02-structured-output-and-validation.md) · [目录](../README.md)

本章解决一个核心问题：模型生成的是建议，程序怎样把它变成可安全处理的数据。具体厂商对 JSON mode、JSON Schema 和严格模式的支持不同，必须查准确型号文档；不把 OpenAI-compatible 当成功能完全相同。[模型说明书参数导航](https://github.com/normalpeople553/HowToCallLLM/blob/main/docs/%E5%8F%82%E6%95%B0%E8%AF%B4%E6%98%8E%E4%B8%8E%E8%B0%83%E5%8F%82.md)

## 1. 三层契约

| 层次 | 要回答的问题 | 负责方 |
|---|---|---|
| 语法 | 是否能解析为 JSON | JSON 解析器 |
| 结构 | 字段、类型、必填项和额外字段是否符合 Schema | 应用侧校验器 |
| 业务 | 订单是否存在、当前用户是否有权操作、状态是否允许变更 | 业务服务 |

JSON Schema 的 `required` 用于声明必须出现的属性；`additionalProperties: false` 可以拒绝未声明的额外属性。这些是结构校验，不是权限校验。[JSON Schema 对象参考](https://json-schema.org/understanding-json-schema/reference/object)

## 2. 从最小 Schema 开始

下面是数据契约，不是可执行的模型 API 示例：

```json
{
  "type": "object",
  "properties": {
    "order_id": {"type": "string", "minLength": 1},
    "action": {"type": "string", "enum": ["query", "cancel"]}
  },
  "required": ["order_id", "action"],
  "additionalProperties": false
}
```

项目建议：只声明当前任务必需的字段，对字符串长度、数值范围和枚举值设边界，不用一个自由文本字段承载一整段可执行指令。Schema 的具体关键字语义以 [JSON Schema](https://json-schema.org/understanding-json-schema/keywords) 为准。

## 3. 完整处理顺序

```text
收到模型输出
  → 确认结束状态与输出非空
  → 解析 JSON（失败就停止）
  → 按 Schema 校验（失败就停止）
  → 做业务校验和授权
  → 如有副作用，请求人工确认
  → 执行并记录可审计结果
```

“让模型重试”不应无限循环。项目建议记录错误类型，只对可修复的格式错误给有限次重试；权限不足、未知工具或业务冲突应直接停止。

## 4. JSON 模式不等于业务正确

DeepSeek 的 JSON Output 文档要求同时设置 `response_format` 并在提示中包含 `json`，且提醒可能出现空内容；这说明调用方必须检查实际回包，不能只看请求参数。[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)

即使某个型号支持严格 Schema，也只能改善结构符合度；应用仍需要自己执行身份、权限、幂等和存在性检查。这是本项目的工程边界。

## 5. 失败处理表

| 失败 | 程序应做什么 |
|---|---|
| 非 JSON | 保留脱敏原始片段，拒绝执行；可有限重试 |
| Schema 不符 | 返回具体字段错误，不自动“猜”值 |
| 业务不符 | 返回可理解的业务错误，不让模型绕过规则 |
| 需要高风险动作 | 生成确认摘要，等待明确授权 |
| 未知或额外字段 | 拒绝并记录，不透传到下游 |

## 检查表

- [ ] 准确型号的官方文档明确支持所用模式；
- [ ] JSON 解析、Schema 校验和业务校验是三个独立步骤；
- [ ] 未知字段、超长字符串和越界数值会被拒绝；
- [ ] 校验失败不会进入真实工具；
- [ ] 不把“结构合法”误当成“用户有权执行”。
