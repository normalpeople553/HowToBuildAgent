# 05 · 检索与知识库

[English](../en/docs/05-retrieval-and-knowledge-bases.md) · [目录](../README.md)

RAG 的原始论文将参数化模型与可检索的非参数化外部记忆结合用于生成。工程上可以把它理解为：先找到与问题相关的资料，再让模型只基于选中资料和明确的任务生成答案。[原始 RAG 论文](https://arxiv.org/abs/2005.11401)

## 1. 不要把 RAG 等同于“上传文件”

| 阶段 | 输入 | 输出 | 需要单独测试什么 |
|---|---|---|---|
| 摄取 | 原始文件 | 带权限和版本的规范文本 | 是否丢页、乱序、OCR 错误 |
| 切块 | 规范文本 | 可检索片段 | 边界是否切断语义或表格 |
| 索引 | 片段与元数据 | 检索索引 | 版本、租户、标签是否可过滤 |
| 检索 | 用户问题 | 候选片段 | 正确证据是否进入 top-k |
| 重排 | 候选片段 | 最终证据 | 相关性与权限是否同时满足 |
| 生成 | 问题与证据 | 回答与引用 | 结论是否能被证据支持 |

项目建议为每个片段保留 `document_id`、`version`、`location`、`tenant`、`acl`和可追溯原文。没有这些元数据，系统很难做权限过滤、引用定位和过期更新。

## 2. 先过滤权限，再给模型

知识库的访问权不应由模型判断。检索时就应带用户、租户和资源权限过滤，未授权片段不应进入提示或日志。OWASP 将向量与嵌入弱点列为 LLM 应用风险之一，需要同时关注数据隔离、中毒和检索泄漏。[OWASP LLM Top 10](https://genai.owasp.org/llm-top-10/)

## 3. 证据和指令分开

检索到的文本是不可信数据，其中可能包含伪装成指令的内容。在提示中用清晰边界标识证据，要求模型不执行证据里的指令；但不要把这一句提示当成唯一防线。工具权限、输出校验和人工确认仍要在应用层强制。[OWASP Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)

## 4. 引用是产品功能，不是装饰

一个可核对的回答应将结论映射到返回的文档 ID 和位置，前端再将它渲染为可点击来源。不让模型自由编造 URL；引用地址由程序根据检索结果生成。当证据不足或互相冲突时，产品应允许回答“资料不足”并显示冲突来源。

## 5. 测试检索与生成

建立一组带正确文档 ID 的问题，分开统计：检索命中率、无答案拒答、权限泄漏、引用正确性和最终任务成功率。如果正确文档从未进入候选，不应只靠改提示词修复。

## 检查表

- [ ] 原文、片段、版本和位置可追溯；
- [ ] 权限过滤发生在检索/工具层，不交给模型；
- [ ] 检索内容按不可信输入处理；
- [ ] 引用由程序映射真实文档，不由模型编 URL；
- [ ] 检索质量和答案质量分开评估；
- [ ] 有文档删除、过期和重建索引流程。
