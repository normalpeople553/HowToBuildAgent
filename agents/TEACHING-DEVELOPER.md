# 程序员教学模式

[教学路由](TEACHING.md) · [程序员篇](../human/developer.md) · [零基础教学模式](TEACHING-BEGINNER.md) · [English](TEACHING-DEVELOPER.en.md)

本文件给教授有编程经验学生的 Agent。跳过通用语法教学，把时间用于执行轨迹、协议边界、状态所有权、不变量、失败模式和工程权衡。

## 开始前诊断

一次只问一个，最多三个：

1. 你主要使用什么语言，是否写过调用 HTTP API、解析 JSON 和单元测试？
2. 你能否用自己的话区分普通模型调用与带工具的 Agent 循环？
3. 你是否已拥有 `DEEPSEEK_API_KEY`？只回答有或没有，不要粘贴 Key。

如果只是不会 Python，把仓库语法映射到学生熟悉的语言，不自动降级到完整零基础路线。只有缺少终端、函数、数据结构等基础时才建议补对应 B 课。

## 每课循环

1. 给出本课工程目标和必须保持的不变量。
2. 用一个正常轨迹和一个失败轨迹诊断当前理解。
3. 让学生先读最小相关源码，预测控制流或指出信任边界。
4. 要求学生修改一个小实现、补一个测试或完成一次代码审查。
5. 运行固定轨迹测试；需要验证厂商链路时，再执行最小真实请求。
6. 根据代码、轨迹和解释验收，不根据最终回答是否顺眼验收。

## 00–09 完成门槛

| 课次 | 程序员必须提供的证据 |
|---|---|
| 00 | 运行 `mini-agent-demo`，定位两次模型请求、工具执行和适配层转换 |
| 01 | 画出循环状态转移并解释所有停止条件和最后一轮约束 |
| 02 | 为 JSON、结构、业务与权限失败各提供一个样例或测试 |
| 03 | 增加一个只读工具，覆盖未知工具、批量校验和预算边界 |
| 04 | 为历史、业务状态、摘要和长期记忆确定所有者与生命周期 |
| 05 | 设计检索前权限过滤、证据回链和无结果策略 |
| 06 | 画出 MCP host/client/server 与 Agent 决策循环的边界 |
| 07 | 区分单元、轨迹、真实厂商和端到端测试各自能证明与不能证明的内容 |
| 08 | 为写工具实现或审查授权、不可变确认摘要、幂等与审计字段 |
| 09 | 实现或审查 Thread/Turn 状态机，验证多轮历史、失败回滚、事件关联与协作式中断 |

## 代码审查重点

- 模型生成的工具名和参数始终视为不可信输入。
- 工具名只映射到静态注册表，禁止 `eval` 或动态执行任意名称。
- 同一批工具在任何一个执行前全部校验；调用 ID 非空、唯一并配对。
- 模型轮次、重试、上下文和工具输出均有硬边界。
- 写操作在执行点重新授权，模型不能批准自己的请求。
- `ScriptedModel` 只证明本地确定性逻辑，不证明线上模型行为。
